
### RTIC Distributions

#### Definition

An RTIC distribution is a Rust crate that exposes the RTIC attribute proc-macro **implemented for a specific hardware architecture, a specific microcontroller, or a specific target use case**. For example, there could be a distribution for single-core Cortex-M devices, a distribution tailored for the multicore RP2040, a distribution for RISC-V soft-cores, and so on.

A distribution crate is responsible for:

1. Implementing the low-level hardware-specific details and providing/binding them to the hardware-agnostic RTIC compilation passes.
2. Integrating a selection of compatible compilation passes and optionally exposing them to the user as Cargo features.
3. Exposing the RTIC `#[<distro>::app]` proc macro generated by `RticMacroBuilder` after the previous two steps are complete.

![stack](https://github.com/zakimadaoui/rtic-mc-experiments/blob/main/distributions/modular_arch.white.png?raw=true)

Distributions make RTIC codebase growth more controllable and provide an alternative to the older approach where all hardware-specific details belonged to a single crate maintained by the RTIC team, and users selected a target by enabling a corresponding feature.

#### Important: new distributions are out-of-tree

This repository maintains the core framework and a set of reference distributions. Distributions for new hardware targets should be developed as separate crates in their own repositories. They are not merged into the core RTIC project.

#### How to implement a distribution using `rtic_core::RticMacroBuilder`

A distribution typically consists of two crates: a library crate that users depend on and a proc-macro crate that defines the macro.

The macro crate constructs an `RticMacroBuilder`, registers the passes it wants, and provides the target-specific backend implementation:

```rust
use proc_macro::TokenStream;
use rtic_core::RticMacroBuilder;

#[proc_macro_attribute]
pub fn app(args: TokenStream, input: TokenStream) -> TokenStream {
    let mut builder = RticMacroBuilder::new(MyCoreBackend);
    builder.bind_pre_core_pass(rtic_sw_pass::SoftwarePass::new(MySwBackend));
    builder.bind_pre_core_pass(rtic_auto_assign::AutoAssignPass);
    builder.build_rtic_macro(args, input)
}
```

The library crate then re-exports the macro:

```rust
pub use my_rtic_macro::app;

pub mod export {
    // Re-export target-specific runtime helpers
}
```

For a working reference, see the `rp2040-rtic` distribution. For a conceptual starting point, see `distributions/distribution-template/`. Note that the template is intentionally minimal and is not expected to compile against the current `rtic-core`.
